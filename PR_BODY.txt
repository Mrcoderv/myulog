PR title: Improve synthetic generators: realistic raw messages (Faker), agentic README-like templates, and raw-mirror behavior

Summary
- Improve synthetic data generators to emit realistic, parser-friendly raw messages and multi-line stacktraces.
- Add Faker to generate human-like sentences and seeded deterministic output.
- Add agentic templates that closely match examples in `schemas/agentic/README.md` (plan_created, tool_selected with ranking, LLM inference with tokens/cost, guardrails warn).
- Change raw-mirror behavior so raw files contain only `{ "@timestamp", "@message" }` where `@message` is the raw textual log line (`meta.raw_message`), instead of embedding the full normalized JSON.
- Fixed a bug where message generation referenced the log dict before it was built (ordering fix).

Files changed
- `data/generator/generator.py` — add Faker support, `generate_message()`, `generate_stacktrace()`, agentic templates, seeding for reproducibility.
- `data/generator/agentic_generator.py` — populate `meta.raw_message` using the new templates.
- `data/generator/cv_generator.py` — use `generate_message(...)` for `meta.raw_message`.
- `data/generator/main.py` — raw mirror now writes `@message` = `meta.raw_message`; falls back to compact JSON if missing.
- `pyproject.toml` — add Faker dependency (for local tests and demo generation).

Why
- Previously, raw messages were machine-like random strings embedded in normalized JSON, which made parser training and manual inspection difficult.
- The new raw format better reflects real-world logs (timestamp + free-text message) and produces messages that match documented examples. This directly addresses the concerns raised by the team:
  - Yhya: raw logs now include only timestamp and message fields in the raw-mirror output.
  - Ayman: agentic messages now include "Plan created" and "Tool selected" styles that the parser expects (README examples were used as templates).

What I ran / validation performed
- Installed Faker into the workspace venv and seeded the generator.
- Generated normalized and raw-mirror files locally (using `.venv` Python) for domains `agentic`, `cv`, `api`, `llm`.
  - Output files: `data/synthetic/log_{domain}_valid.jsonl`, `data/synthetic/log_{domain}_invalid.jsonl`, and `data/synthetic/raw/{domain}_raw.jsonl`.
- Confirmed sample outputs:
  - Agentic raw example: `{"@timestamp":"2025-01-01T03:53:49.000Z","@message":"Agent created 2-step execution plan for user query"}`
  - CV raw example: `{"@timestamp":"2025-01-01T07:14:22.000Z","@message":"Processed 4013 images from COCO using ResNet50 on NVIDIA V100 - avg latency 71.602 ms"}`
- Confirmed normalized logs still contain structured fields and `meta.raw_message` preserves the raw text.

Validation checklist for reviewers
- Raw-mirror files contain only `@timestamp` and `@message`.
- Agentic `@message` lines contain README-like tokens: "Agent created", "Tool selector", "LLM inference", "[WARN] Safety check".
- Normalized JSON contains expected fields (`step_kind`, `workflow_id`, `step_id`, `tool_name`, `input_summary`, `output_summary`, `status`, `duration_ms` / `cost` where applicable).
- Seeded determinism: running with same `-s` seed yields identical files.
- Parsers should match the new raw lines for `plan_created` and `tool_selected` cases — run parser(s) and report parse rate.
