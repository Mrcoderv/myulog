# ULog

ULog is an initiative to standardize and make actionable the telemetry generated by AI systems. By introducing versioned JSON logging contracts, a normalization and enrichment pipeline, and a deterministic classification engine, ULog ensures that heterogeneous logs from APIs, LLMs, agents, and CV pipelines become reliable, auditable signals.

## Schemas

### Core/API Contract Schema (`schemas/core_api.schema.json`)

The Core/API Contract Schema defines a deterministic JSON structure for logging API calls. It captures the service name, endpoint path, HTTP method, request latency, outcome status, and structured error details for failed requests.

#### Schema Overview

Each event includes:

| Field           | Type                | Description                                                                                | Required |
| --------------- | ------------------- | ------------------------------------------------------------------------------------------ | -------- |
| `timestamp`     | `string` (ISO 8601) | When the event occurred. Example: `2025-10-09T12:34:56Z`.                                  | ✓        |
| `request_id`    | `string`            | Unique ID for tracing a request across services.                                           | ✓        |
| `service`       | `string` (1–100)    | Name of the service emitting the log.                                                      | ✓        |
| `endpoint`      | `string`            | API path starting with `/` (regex `^/.*$`).                                                | ✓        |
| `action`        | `string`            | Operation, one of: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`, `INTERNAL`. | ✓        |
| `result`        | `string`            | Outcome, one of: `success`, `error`, `timeout`, `rejected`, `throttled`.                   | ✓        |
| `latency_ms`    | `number` (≥ 0)      | Duration in milliseconds.                                                                  | ✓        |
| `env`           | `string`            | Environment, one of: `production`, `staging`, `development`, `test`.                       | ✓        |
| `error`         | `object`            | Error details with `code` and `message` properties.                                        | ✓*       |
| `error.code`    | `string`            | App-specific error code (e.g., `AUTH_INVALID_CREDENTIALS`).                                | ✓*       |
| `error.message` | `string` (1–500)    | Human-readable error message.                                                              | ✓*       |
| `http_status`   | `integer` (100–599) | HTTP status code, if applicable.                                                           | ✗        |
| `metadata`      | `object`            | Free-form context (e.g., `client_id`, `region`).                                           | ✗        |

**\* Conditional**: `error` and its nested fields are required only when `result` is `error`, `timeout`, or `rejected`.

#### Schema Constraints

- **`endpoint`** must start with `/` (enforced via regex pattern `^/.*$`)
- **`service`** must be 1-100 characters in length
- **`latency_ms`** cannot be negative (minimum: 0)
- **`http_status`** must be between 100-599 if provided
- **`error.message`** must be 1-500 characters when present
- **`error`** object (with both `code` and `message`) is mandatory when `result` is `error`, `timeout`, or `rejected`
- No additional properties allowed at the root level (strict schema)

#### Example 1 — Success (GET)

```json
{
  "timestamp": "2025-10-09T12:34:56Z",
  "request_id": "req_1234567890",
  "service": "user-service",
  "endpoint": "/v1/users/123",
  "action": "GET",
  "result": "success",
  "latency_ms": 42,
  "env": "staging",
  "http_status": 200,
  "metadata": {
    "client_id": "cli_web",
    "region": "eu-west-1"
  }
}
```

#### Example 2 — Auth Error (POST)

```json
{
  "timestamp": "2025-10-09T12:35:10Z",
  "request_id": "req_1234567891",
  "service": "auth-service",
  "endpoint": "/v1/login",
  "action": "POST",
  "result": "error",
  "latency_ms": 85,
  "env": "production",
  "http_status": 401,
  "error": {
    "code": "AUTH_INVALID_CREDENTIALS",
    "message": "Invalid username or password"
  },
  "metadata": {
    "client_id": "web",
    "ip": "203.0.113.10"
  }
}
```
